### archify 踩坑记录（可复用）

1. 组件带 `sources` 就必须配 `meta.repository`（GitHub URL + 40 位 sha），且 validate/deliver/visual-check 都要加 `--repo-root .`，否则报 repository-evidence 错误。
2. `route: "straight"` 会产生对角线，artifact 检查 `orthogonal_arrows` 必挂。只能走正交路由。
3. `via` 不会自动正交：via 点必须与起止端口共轴（同 x 或同 y），否则直接画成斜线。想拐弯要写 `via: [[起端口x, 拐点y],[终端口x, 拐点y]]`，且终点 x 必须精确等于目标端口中心（如 1172.5 而非 1172），否则 `endpoint-side-direction` 报 final segment 不垂直。
4. 竖直边的标签默认落在「源节点中心 +22px」，会压住源节点；必须给 `labelDy`（实测 +40 安全）。水平边的标签落在空隙中点，空隙 ≥ 90px 时 71px 宽的标签能过。
5. 从同一节点扇出到一列节点时，自动路由会共用同一条 channel（x = 空隙中点），导致标签互相压线（label-route-clearance < 4px）。根本解法是**减少扇出数**：把部分目标节点挪到底部行，让边变成「直下」而不是「右转再竖走」。
6. `composition/desktop-readability`：1440 视口下可用图宽按 930px 估算，viewBox 宽度需 ≲1394，否则 9px 的 sublabel 投影低于 6px 下限。最终用组件宽 165 + 列间距 90 + viewBox 1320x840 通过。
7. `visual-check` 在本机对环境敏感：与并发的 Chrome DevTools 实例冲突时报「Chrome closed with exit code 0」。本次 3 次尝试均失败，未取得浏览器证据（同目录下 `claimflow-main-graph` 的 visual-check 是并发进程跑成功的）。
