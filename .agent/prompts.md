# Prompt 模板参考

> 每个阶段对应的 Prompt 模板，直接复制到任意 Agent 对话框使用。
> 将 `[占位符]` 替换为你的实际内容。

---

## Phase 1 — 需求定义

```
我要构建一个 [一句话描述项目]。

请先问我 3-5 个澄清问题（目标用户、核心功能、MVP 范围、技术约束），
等回答后，在 .agent/spec.md 中写：
1. 问题陈述：项目解决什么问题
2. 目标用户：谁会用
3. MVP 功能列表：每条附验收标准
4. 非目标：明确不做什么
5. 技术约束：必须满足的限制

写完让我确认，确认后再进入下一步。
```

## Phase 2 — 架构设计

```
读取 .agent/spec.md，设计技术架构。

在 .agent/plan.md 中写：
1. 技术选型：每个选择附一句理由
2. 目录结构：完整文件树
3. 数据模型：表名 + 字段 + 类型 + 约束 + 关系
4. API 设计：端点列表 + Method + 请求/响应格式
5. 第三方依赖：包名 + 版本 + 用途
6. 关键决策记录：同步写入 .agent/decisions.md

写完让我确认。
```

## Phase 3 — 任务拆解

```
读取 .agent/plan.md，拆解实现任务。

在 .agent/tasks.md 中写一个有序清单，格式：
- [ ] T0XX: [任务名] | 依赖: [T0XX或无] | 涉及文件: [路径] | 验收: [标准]

规则：
- 粒度：1 个任务 = 1 个可独立验证的功能点
- 依赖：标注前置任务编号
- 顺序：基础设施数据层 → 核心业务 → API → 辅助 → 测试 → 文档
- 验收：写明怎么验证（运行什么命令、看什么结果）

写完让我确认。
```

## Phase 4 — 逐任务构建（循环调用）

```
读取 .agent/tasks.md，实现下一个未完成的任务。

要求：
1. 只实现这一个任务，不要超前做后面的
2. 完成后在 tasks.md 中将 [ ] 改为 [x]
3. 在 progress.md 中追加记录（任务编号、文件变更、验证方式）
4. 单独 git commit
5. 告诉我验证方法，等我确认后再做下一个
```

## Phase 5 — 验证交付

```
所有任务已完成。进行最终验证：

1. 运行全部测试，修复所有报错
2. 逐条对照 .agent/spec.md，检查 MVP 功能是否全部实现
3. 检查 edge case（空输入、异常路径、权限边界）
4. 配置 CI 流水线（.github/workflows/ci.yml）：lint + test，push 自动触发
5. push 到 GitHub，确认 CI 全绿
6. （可选）配置 CD：main 分支合并后自动部署
7. 更新 README.md：安装步骤、运行方式、API 文档、CI 徽章
8. 在 progress.md 写最终总结

报告：已完成 / 有问题 / 下一步建议。
```

## 上下文恢复 Prompt

> 新会话或会话中断后，用这个 Prompt 让 Agent 快速恢复状态。

```
读取 .agent/ 目录下所有 .md 文件（spec.md, plan.md, tasks.md, progress.md, decisions.md），
理解当前项目状态。

报告：
1. 项目目标（来自 spec.md）
2. 已完成的任务（tasks.md 中 [x] 的项）
3. 下一个待执行的任务
4. 有无未解决的问题

等我确认后再继续执行。
```

## 回退 Prompt

> 某个任务出问题，需要回退时使用。

```
任务 [T0XX] 实现有问题，需要回退。

操作：
1. git reset 到 [T0XX] 之前的 commit
2. 在 tasks.md 中将 [T0XX] 改回 [ ]
3. 在 progress.md 中记录回退原因
4. 重新实现 [T0XX]，这次注意 [具体问题]
```
