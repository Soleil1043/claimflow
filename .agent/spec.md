## 1. 问题陈述

多险种理赔案件人工审核成本高、周期长（件均数天），且各险种材料体系与核赔路径差异大，
固定流程系统无法覆盖。本项目构建 **LLM Orchestrator-Worker 多智能体核赔平台**：
受理期自动分类险种，Orchestrator 动态调度专业 Worker（材料审核/保单核验/风控筛查/
责任认定/金额理算/决定书生成）完成自动核赔；领域知识以 skill 作业规程包承载；
低风险小额案件自动签发《理赔决定书》，其余精准转人工。

> 定位延续：求职作品集，按真实业务 PoC 原型级别设计——审批流可审计、金额确定性、
> 数据合规均按生产标准取舍，外部系统用可信 Mock 起步。

## 2. 目标用户

- **C 端客户**：提交理赔申请与材料、按指引补件、查看进度与决定书
- **核赔坐席**：复核签批、补件催办、升级处理（工作台）
- **运营/技术评审**：自动结案率、路由准确率、件均耗时、全链路审计回放

## 3. MVP 功能列表

> 每条有可验证验收标准。不在列表的不做。多险种架构原生（case_type 枚举 +
> skill 包机制），**worker 首批仅医疗险 pack**；未上线险种受理期转人工（F01）。

| 编号 | 功能名称 | 描述 | 验收标准 |
|------|---------|------|---------|
| F01 | 案件受理与幂等 | 提交案件（险种/保单/金额/事故描述/材料），LLM 结构化分类险种；重复提交幂等 | 重复 case 返回既有结论不重复执行；未上线险种转人工受理；受理记录落库 |
| F02 | 材料上传与解析 | 图片/PDF/Word 两段式提取（vision + 文本），Mock 兜底 | 真实材料字段提取正确；解析失败接口不报错走兜底 |
| F03 | Orchestrator 动态调度 | RoutingDecision 结构化输出 + 并行 Send 派发 + **前置条件守卫** + 失败兜底默认计划 + 决策审计落 case_events | 金样本路由一致率 ≥95%；守卫注入用例 100% 拦截；LLM 失败走兜底案件不阻塞；每案件调度调用 ≤15 |
| F04 | 材料审核（医疗险 pack） | OCR/解析→结构化抽取→完整性校验→补件流转 | 关键字段 F1 ≥95%；完整性规则纯函数单测全覆盖 |
| F05 | 保单核验 | 有效性/等待期/除外责任/限额核验 | 金样本判定一致；边界（过期/等待期内）单测 |
| F06 | 风控筛查 | 欺诈规则评分 + 黑名单 + 理赔频率（Mock） | 规则评分与金样本期望一致；高风险短路转人工 |
| F07 | 责任认定 | ReAct Agent + 条款 RAG，输出结论/条款引用/置信度 | 责任认定一致率 ≥90%；引用条款可溯源 |
| F08 | 金额理算 | 确定性计算（Decimal），扣减明细/部分责任/限额 | **金额正确率 100%**（错一分即挂）；无 LLM 参与 |
| F09 | 决定书生成 | 模板 + LLM 撰写，版本化落库 | 要素齐备（结论/金额/依据/救济途径）；版本可追溯 |
| F10 | 合规门（静态） | 三态 PASS/MODIFY/REJECT + 修订闭环 + **金额一致性断言** + PII 脱敏；decision_generate→合规门为静态边不可绕过 | 红线漏放 0；金额注入用例 100% 拦截；图结构断言证明无旁路 |
| F11 | 分级自动签发 | 低风险+责任明确+金额阈值内自动出书；否则转人工 | 金样本签发/转人工路由 ≥95%；阈值全部配置化 |
| F12 | HITL 人工介入 | SUPPLEMENT/REVIEW/ESCAPE 三类工单；interrupt 挂起 + Command(resume) 恢复 | 补件→材料审核重跑；签批→签发；REJECT→坐席结论过合规复审；跨服务重启可恢复 |
| F13 | 坐席工作台 | 工单类型筛选、案件时间线（含路由决策审计）、签批表单、补件上传 | 操作链路可用；npm build 通过 |
| F14 | 案件查询 | 进度/阶段结论/决定书/审计事件查询 API | API 单测；审计事件完整可回放 |
| F15 | 案件提交演示门户 | chatui 改造（D038）：提交+传材料→进度时间线→决定书查看/补件 | 全链路演示可走通；截图目检 |
| F16 | 评测体系与上线门 | 金样本 150-200 案件 + 判分器 + 复用评测框架 | 硬门：金额 100%/红线 0/守卫拦截 100%；软门：路由 ≥95%/F1 ≥95%/责任 ≥90% |
| F17 | 可观测 | 业务指标（自动结案率/转人工率/阶段耗时/调度调用数/守卫修正数）+ OTel 追踪 | 指标与面板产出；每案件一 trace 可回放 |

## 4. 非目标（明确不做什么）

- **车险/财产险/意外险 worker pack**：二期任务（架构与受理分发已就绪）；若用户要求进首批需追加任务
- 真实第三方系统对接（保单/黑名单为可信 Mock）
- 电子签章、医保结算对接、影像智能审核
- 用户注册登录/多租户/权限体系（PoC 单租户）
- 短信/小程序通知、监管报送导出
- 长期记忆（核赔无跨会话记忆需求；v1 Store 代码归档保留）

## 5. 非功能需求

- **金额确定性**：全链路 Decimal，禁止 float；决定书金额与理算结果机器断言一致
- **可审计**：阶段结论与 orchestrator 路由决策 append-only 落库，案件全流程可回放
- **数据合规**：PII 脱敏输出；外部服务 Mock 起步、LLM 走可配置供应商
- **性能**：单案件端到端 ≤3 分钟（Mock 依赖下，P95）；调度调用预算 ≤15 次/案件
- **配置化**：自动签发阈值/置信度门槛/轮数上限/调用预算全部进 pydantic-settings
